### Task Summary

**One-sentence description**: Make `createWorktree` overlay the parent repo's uncommitted working-tree state (untracked / modified / staged / deleted / renamed files) into the new isolated worktree, gated by a new `carryUncommitted` spawn param (default true, skipped when `baseRef` is set).

**Goal**: An isolated subagent dispatched with `isolate: true` from a parent that has uncommitted work (e.g. an unwritten plan doc at `docs/plans/foo.md`) can read/write those files in its worktree instead of hitting ENOENT on first read.

### Implementation Specification

```ts
carryUncommitted: Type.Optional(
    Type.Boolean({
        description: "Carry the parent's uncommitted working-tree state (untracked, modified, staged, deleted files) into the isolated worktree at creation, so the subagent sees what the orchestrator prepared. Default: true. Ignored when baseRef is set — the worktree then branches from that ref's tree. Set false to reproduce HEAD-only behavior.",
        default: true,
    }),
),
```

**2. `createWorktree` signature** (line 445): add a fourth parameter `carryUncommitted: boolean = true`. Keep the return shape unchanged.

**3. Call site** (line 2040): `await createWorktree(cwd, sessionId, params.baseRef, params.carryUncommitted ?? true)`.

**4. The overlay** — inside `createWorktree`, after the `worktree add` call succeeds (after the `if (wtResult.exitCode !== 0) return null;` check, ~line 484) and before the return (~line 488). Guard: only run when `carryUncommitted && !baseRef` — when `baseRef` is set, preserve today's HEAD-only behavior entirely.

Algorithm (parent repo root `topLevel` is already in scope; `worktreePath` too):

1. Enumerate, non-destructively (read-only on the parent — no `git stash`, no `git checkout`, no index writes):
   `git(["status", "--porcelain=v1", "-uall", "-z"], topLevel)`
   This respects `.gitignore` (do NOT switch to a raw fs walk) and lists every untracked file individually (`-uall`).
2. Parse the NUL-separated output (`stdout.split("\0")`, drop trailing empty token). Record format:
   - Normal entry: `XY path` where `X` = index status, `Y` = worktree status (either may be a space), then a space, then the repo-relative path. Parse as `const x = rec[0], y = rec[1], p = rec.slice(3)`.
   - `??` = untracked. `R`/`C` in `X`: the record path is the NEW path and the NEXT NUL token is the ORIGINAL path.
3. For each entry, mirror into the worktree at the same repo-relative path (only ever write under `worktreePath`):
   - `??` (untracked), or file exists at `topLevel/path` and status is any of M/A/T/U in either column (includes ` M`, `M `, `A `, `MM`, `AM`, etc.): copy bytes `topLevel/path` → `worktreePath/path`, preserving mode (exec bit — `cp -p` semantics), creating parent dirs with `fs.mkdirSync(dirname, { recursive: true })`.
   - `D` in either column: `rm` the file at `worktreePath/path` (best-effort; ignore already-absent).
   - `R` (status[0] === "R", record path is new, next token is orig): remove `worktreePath/orig`, copy `topLevel/new` → `worktreePath/new`.
   - `C` (status[0] === "C"): copy `topLevel/new` → `worktreePath/new` (the original is already present from checkout).
   - **Path safety**: reject any entry whose path is empty or contains `..` (any segment or substring) — skip it. Paths come from git so this is defense-in-depth, not an expected case.
4. Symlinks: copy the link as-is — do NOT dereference into the worktree. Use `fs.lstat` on the source; if it's a symlink, `fs.readlinkSync` + `fs.symlinkSync` (same link target string) in the worktree; else copy bytes and `fs.chmodSync` the target to the source's mode (this guarantees exec-bit preservation regardless of `fs.cp` semantics).
5. Never touch `.git` in the parent or the worktree (status never lists `.git`, but assert-skip anything under `.git/` anyway).
6. Do NOT `git add` in the worktree — carried files surface as untracked/modified, which is the intent (visible to the subagent; the completion auto-commit can pick them up).
7. Failure semantics: the overlay is best-effort. Wrap it in try/catch; on error, log via `debugLog` and CONTINUE (do not return null — that would kill the dispatch). Degradation is exactly today's documented HEAD-only behavior. Overlay errors must not throw out of `createWorktree`.

Style: follow the function's existing conventions — `git()` helper with `topLevel` as cwd, `debugLog` with `PI_ASYNC_DEBUG` timing where non-trivial, no comments restating the code. Keep the diff tight.

**Required test boundary**: The extension's real boundary (subagent dispatch) requires the pi runtime, which a unit test cannot invoke — `index.ts` is NOT importable by node/bun (`typebox` and `@earendil-works/*` resolve only under jiti; verified). Therefore the focused test follows the `test-subject.cjs` precedent: a standalone node script that exercises the carry semantics end-to-end at the git/fs layer with REAL temp repos and REAL `git worktree add`, mirroring the carry logic (parsing + copy/delete decisions) exactly as implemented in `index.ts` — keep the mirror in sync with the implementation, and comment both sides of that contract. ### Invariants

- **Parent untouched**: the only git command run against the parent for carry is `status --porcelain=v1 -uall -z` (read-only). No stash, no checkout, no reset, no index writes, no config changes in the parent.
- **Write scope**: writes happen only under `worktreePath`. Never `topLevel`/`<path>`.
- **`.gitignore` respected**: enumeration uses `git status` only; never a raw directory walk.
- **Mode preservation**: exec bit survives (`cp -p` semantics); symlinks copied as links.
- **Default behavior**: `carryUncommitted` defaults to TRUE at both the schema and `createWorktree` levels. `baseRef` present ⇒ carry never runs.
- **No worktree `git add`**: carried files appear as modified/untracked, not staged.
- **`worktree add` failure is still fatal** (returns null, as today). Only overlay failure is best-effort.
- **`preCommitSteps` unchanged** (lines 522–560), including the `WO-*.md` unstage.
- **Return shape and existing param schemas unchanged**; no new exports from `index.ts`.
