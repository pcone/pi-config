### Task Summary

**One-sentence description**: Add a full-width 3-day logarithmic activity timeline as a new bottom row of the custom footer in `extensions/footer-session-id.ts`.

**Goal**: A footer row that shows, per time bucket over the last 3 days, whether user messages (solid), only LLM-driven messages (half/dithered), or nothing (empty) occurred in that bucket, with a distinct marker on the bucket where the session started. The scale must be fixed (3-day window, log-uniform in age) so sessions are visually comparable.

### Implementation Specification

**Detailed requirements**:

All new code lives in `extensions/footer-session-id.ts`. The file already defines `type Theme = { fg: (color: string, text: string) => string; bold: (s: string) => string }` — reuse it. Constants:

```
WINDOW_MS   = 3 * 24 * 60 * 60 * 1000  // 259 200 000
MIN_AGE_MS  = 60 * 1000                // 60 000 (log floor)
R_LOG       = Math.log(WINDOW_MS / MIN_AGE_MS)  // ln(4320) ≈ 8.37
```

**1. `export function timelineColumn(ageMs: number, width: number): number`** — map an age (ms) to a column index, left = 3 days ago, right = now:

```
f     = ln(max(ageMs, MIN_AGE_MS) / MIN_AGE_MS) / R_LOG   // ∈ [0, 1) for in-range ages
col   = width − 1 − floor(f * width), clamped to [0, width − 1]
```

- `ageMs < MIN_AGE_MS` (including 0 and negative/future timestamps) → `width − 1` (rightmost).
- `ageMs ≥ WINDOW_MS` → clamped to 0 (leftmost) *by this function*; the exclusion of out-of-window messages happens in `computeTimelineCells` (step 2), so `timelineColumn` itself is a pure clamp.
- `width < 1` → return 0.

**2. `export type TimelineCell = { status: "solid" | "half" | "empty"; isSessionStart: boolean }`** and **`export function computeTimelineCells(entries: unknown[], nowMs: number, width: number, sessionStartMs: number | undefined): TimelineCell[]`** — returns exactly `width` cells, `isSessionStart` set on the single column containing `sessionStartMs` (via `timelineColumn(nowMs − sessionStartMs, width)`; never set when `sessionStartMs` is `undefined` or its age ≥ `WINDOW_MS` — out-of-range start renders no marker).

Per entry, defensively read only `entry.timestamp` (ISO string, like the existing `lastActivityMs` helper) and, for `entry.type === "message"`, `entry.message.role`. Skip entries with unparseable timestamps. Classification per column (in precedence order):

- **solid** — any message with role `user`
- **half** — no `user`, but any message with role `assistant`, `toolResult`, or `bashExecution`
- **empty** — otherwise

Deliberately ignored: all non-message entries (`model_change`, `thinking_level_change`, `compaction`, `branch_summary`, `custom`, `custom_message`, `label`, `session_info`, …) and message roles not in the set above (`custom`, `compactionSummary`, `branchSummary`). This is a documented design decision — do not "improve" it.

Messages with `nowMs − ts ≥ WINDOW_MS` are excluded from the window entirely (do not clamp them into the leftmost column — the window is a strict 3 days).

**3. `export function resolveSessionStartMs(headerTimestamp: string | undefined, entries: unknown[]): number | undefined`** — `Date.parse(headerTimestamp)` when parseable; otherwise the first entry's parseable `timestamp`; otherwise `undefined`. (The footer passes `sm.getHeader()?.timestamp`.)

**4. `export function renderTimelineRow(cells: TimelineCell[], theme: Theme, width: number): string`** — one string of exactly `width` visible columns (assert with `visibleWidth` from `@earendil-works/pi-tui`, already imported):

| cell state | renders |
|---|---|
| solid | `theme.fg("accent", "\u2588")` (█) |
| half | `theme.fg("accent", "\u2592")` (▒) |
| empty | `" "` |
| `isSessionStart` (overrides) | `theme.fg("warning", "\u2588")` (█) |

- Marker overrides the underlying char/color regardless of status (one column loses its solid/half signal — accepted tradeoff, documented).
- `width < 1` → return `""`.
- `cells.length !== width` → use `Math.min(cells.length, width)` and pad with spaces to `width` (defensive; should not happen).

**5. Wire into `render(width)`** — after the statuses/quota lines block, as the final line:

```ts
const entries = sm.getEntries();
const startMs = resolveSessionStartMs(sm.getHeader()?.timestamp, entries);
const cells = computeTimelineCells(entries, Date.now(), width, startMs);
lines.push(renderTimelineRow(cells, theme, width));
```

- Extend the local `FooterFactoryCtx` type's `sessionManager` shape with `getHeader(): { timestamp?: string } | null`.
- Always render the row (even when all cells are empty) so footer height is stable.
- Reuse the existing `sm.getEntries()` call if convenient (the usage-aggregation loop already calls it); do not restructure that loop.
- `now = Date.now()` at render time; the existing 30s interval and `onBranchChange` subscription already drive refresh. Do not add timers.

**Required test boundary**: the exported pure helpers (`timelineColumn`, `computeTimelineCells`, `resolveSessionStartMs`, `renderTimelineRow`) imported directly from `../extensions/footer-session-id` — the same boundary the existing `tests/footer-session-id-multiplier.test.ts` uses. These are deterministic input/output transformers; unit tests through this boundary are the primary correctness evidence. Do not test through the footer factory itself (it needs a live interactive-mode ctx).

**Behavior and failure matrix** (each row must have at least one test):

- Window is exactly 3 days; log floor exactly 1 minute; `R = 4320`. No configurable knobs.

**Ordering assumptions**:
- Marker resolution (session start) is independent of cell classification — the marker column is computed once and applied last (override).
- `isSessionStart` does not affect `status` — a marker column's status is still computed normally (the render just shows the marker instead).

**Error handling conventions**:
- Never throw on malformed entries: unparseable timestamps and unknown roles are skipped, matching the file's existing defensive style (`lastActivityMs`).
- Pure helpers must not throw for any input shape (width ≤ 0, NaN timestamps, etc.) — normalize, don't crash.

- The `render()` method's exact local variable flow (stats aggregation, pwd building, quota segment) must be preserved as-is — the implementer must read the full file to avoid disturbing it.
- Row ordering within the footer is significant to the user (rows 1–3 are a designed layout) — append, never insert.

**Relevant decisions from planning session**:
- Scale: fixed 3-day window, log-uniform in age, floor 1 minute. Granularity at the young end ≈ `8.37/W` minutes (sub-minute at readable widths).
- Presentation: bottom footer row; `█` accent = user activity; `▒` accent = LLM-only (dithered, same hue); space = empty; `█` warning = session-start marker (overrides the cell).

- Activity definition: user → solid (highest precedence); `assistant`/`toolResult`/`bashExecution` → half; compaction/branch summaries and non-message entries excluded.
- Strict window: messages older than 3 days and session starts older than 3 days are not rendered.
- Refresh: reuse existing 30s interval + `onBranchChange`; `Date.now()` at render time. No new timers.
