## Task Summary

**One-sentence description**: Make `fetch_url` and the `read` tool convert PDFs to Markdown instead of dumping raw binary into context, and discourage sessions from reading raw PDF bytes.

**Goal**: A fetched PDF URL or a locally-read `.pdf` file never injects raw PDF bytes into model context. Both paths produce converted Markdown (inline when small, saved-to-disk-with-grep-instructions when large, clear error + skill pointer when conversion fails). Sessions are additionally discouraged from raw-PDF reads via a system-prompt note and an on-demand `pdf` skill.

## Background (incident)

Session `019fafc6-15e4-7673-8ebf-5afc631cf92b` called `fetch_url` on Microsoft Research PDFs 6 times. `fetch_url` treats `application/pdf` as "non-HTML" and inlines up to 200KB of raw binary per call (~1.2MB of garbage across 18 fetch_url calls). The core `read` tool has no binary detection either — a local `.pdf` read dumps the same garbage (only images are special-cased in `dist/core/tools/read.js`).

## Implementation Specification

### 1. `extensions/pdf-convert.ts` (new module)

Pure, testable, no `pi` API imports. Exports:

- `PDF_INLINE_MAX_CHARS = 12_000` — same inline cap as fetch-url's existing `INLINE_MAX_CHARS`.
- `PDF_CONVERT_TIMEOUT_MS = 120_000` — pymupdf4llm with OCR can be slow.
- `isPdfContentType(contentType: string): boolean` — `/\bpdf\b/i` test.
- `isPdfBody(body: string): boolean` — prefix sniff on a possibly-lossy decoded string: `/^\s*%PDF-/` against the first ~64 chars. MANDATORY: headers alone are insufficient — the incident URL (microsoft.com research PDF) serves `content-type: text/html` to curl, body is a PDF.
- `isPdfBytes(buf: Uint8Array): boolean` — sniff first bytes via `new TextDecoder("latin1")` (byte-preserving; utf-8 would lossy-decode non-ASCII bytes) then `/^\s*%PDF-/`.
- `type PdfEngine = "pymupdf4llm" | "pdftotext"`.
- `type PdfConversion = { ok: true; markdown: string; engine: PdfEngine } | { ok: false; error: string }`.
- `interface ExecFn` — `(cmd, args, opts?: { timeout?: number; cwd?: string; signal?: AbortSignal }) => Promise<{ stdout: string; stderr: string; code: number }>`. Matches `pi.exec`'s signature (see `dist/core/exec.d.ts` — note `ExecResult.stdout` is a string).
- `createPdfConverter(exec: ExecFn)` returning `{ convert(pdfPath: string): Promise<PdfConversion> }`:
  - Engine availability probed once per process (module-level cache).
  - **pymupdf4llm first**: `python3 -c "import sys, io, pymupdf, pymupdf4llm; pymupdf.set_messages(stream=io.StringIO()); print(pymupdf4llm.to_markdown(sys.argv[1]))" <pdfPath>`. The `set_messages(stream=io.StringIO())` call is REQUIRED — verified that pymupdf4llm prints a "=== Document parser messages ===" preamble + OCR announcements to **stdout**, which would pollute the markdown. Python binary overridable via `PDF_MD_PYTHON` env var.
  - Availability probe: run `python3 -c "import pymupdf4llm"` with short timeout; any nonzero/failure → try pdftotext.
  - **pdftotext fallback**: `pdftotext -layout <pdfPath> -`. Probe via `sh -c "command -v pdftotext"` (or attempt the conversion and check code).
  - If `markdown.trim()` is empty after a successful run → return `{ ok: false, error: "PDF produced no extractable text (scanned pages? tesseract missing?)" }`.
  - If both engines unavailable/failed → `{ ok: false, error: <clear message naming what's missing and the install command: pip install pymupdf4llm, or brew install poppler> }`. NEVER return raw bytes.
  - All execs use `PDF_CONVERT_TIMEOUT_MS` timeout.
- Temp-file helpers writing to `~/.pi/tmp/pdf-convert/` (72h TTL sweep on module load — copy the sweep pattern from fetch-url.ts's FETCH_DIR block):
  - `newTempFilePath(stem: string, ext: string): Promise<string>` — mkdir recursive + unique name (host/hash/ts pattern like fetch-url's `saveFetch`).
  - `saveTempFile(content: string, stem: string, ext: string): Promise<string>` — write utf-8, return path.
- Response builders (pure-ish, testable — they call the temp helpers only in the save branch):
  - `buildFetchPdfResponse(prefix: string, conv: PdfConversion, url: string): Promise<{ content: { type: "text"; text: string }[]; savedPath?: string }>`:
    - ok && ≤ 12K → inline: `${prefix}\n--- body (pdf: <engine> -> markdown) ---\n<markdown>`
    - ok && > 12K → save `.md`, text = `${prefix}\n--- body (pdf: <engine> -> markdown; N chars — saved to disk) ---\nsaved: <path>\nIt's large — don't read it directly. Use bash to grep it (e.g. \`grep -n -A5 'keyword' <path>\`).` (mirror fetch-url's existing large-markdown message style)
    - !ok → `${prefix}\n--- body (pdf conversion failed) ---\n<error>\nUse the \`pdf\` skill for manual conversion (pdftotext -layout or pymupdf4llm).`
  - `buildReadPdfResponse(conv: PdfConversion, filePath: string): Promise<{ content: { type: "text"; text: string }[]; savedPath?: string }>`:
    - ok && small → `Read PDF file [<engine>] — converted to Markdown:\n\n<markdown>`
    - ok && large → same save-to-disk pattern with a one-line note: `PDF files are binary — converted automatically. Don't read raw PDF bytes.`
    - !ok → `Read PDF file — conversion failed: <error>\n\nUse the \`pdf\` skill for manual conversion.`

### 2. `extensions/fetch-url.ts` (modify)

- Import from `./pdf-convert`: `isPdfContentType`, `isPdfBody`, `createPdfConverter`, `buildFetchPdfResponse`, `newTempFilePath`, `PDF_INLINE_MAX_CHARS` (reuse, don't redeclare).
- Build the converter once at module scope: `const pdfConverter = createPdfConverter(pi.exec.bind(pi))` — NO, `pi` is only available inside the factory function; build it inside `execute` lazily or at `registerTool` time inside the factory closure (the factory receives `pi`, so create it at factory top). Follow fetch-url's existing lazy-`_turndown` pattern if preferred.
- In the `execute`, the non-HTML branch currently is: `if (!/\bhtml\b/i.test(contentType) || !body.trim()) { ...truncated passthrough... }`. Before that generic passthrough return, insert a PDF branch:
  - Condition: `isPdfContentType(contentType) || isPdfBody(body)`.
  - Re-fetch with `curl -o`: build a second args array from the same URL/method/headers/data with `-i` REMOVED and `-o <tempPdfPath>` ADDED (keep `-sSL --retry 2 --retry-max-time 10 --max-time <timeout> --max-filesize 52428800 -A <UA>`). WHY: `pi.exec` returns `stdout` as a utf-8-decoded string; writing the decoded body back to disk corrupts binary (verified: 396KB → 626KB, conversion yields 0 chars). `curl -o` writes raw bytes directly. Temp path via `newTempFilePath("pdf", "pdf")`.
  - If the re-fetch fails (exit code ≠ 0) → return error text (curl exit + stderr), do NOT fall through to the corrupted first body.
  - `const conv = await pdfConverter.convert(tempPdfPath)`. Always `rm` the temp pdf file after conversion (unlink; use node:fs `unlink`, best-effort in finally).
  - Respond via `buildFetchPdfResponse(prefix, conv, url)`.
  - Set `details.transform = "pdf"` (extend the union type: `"none" | "readability" | "fallback" | "pdf" | "error"`).
- Update the tool `description` (the `registerTool` block): add a sentence stating PDF responses (detected by content-type or body signature) are converted to Markdown automatically via pymupdf4llm/pdftotext, and that the model should never attempt to read raw PDF bytes.

### 3. `extensions/pdf-read-guard.ts` (new extension)

Follow the rules.ts pattern exactly:

```ts
export default function (pi: ExtensionAPI): void {
  pi.on("tool_result", async (event, ctx) => {
    if (event.toolName !== "read") return;
    if (event.isError) return;
    const p = event.input?.path;
    if (typeof p !== "string" || !p || !/\.pdf$/i.test(p)) return;
    const resolved = path.resolve(ctx.cwd, p);
    const buf = await readFile(resolved).catch(() => null);
    if (!buf || !isPdfBytes(buf)) return;          // read failed or misnamed non-PDF: pass through untouched
    const conv = await pdfConverter.convert(resolved);
    const r = await buildReadPdfResponse(conv, resolved);
    return { content: r.content, details: { ...(event.details ?? {}), pdfConversion: conv.ok ? conv.engine : "error" } };
  });
}
```

Requirements:
- REPLACES the read result content wholesale (no raw bytes reach the model). Do NOT append to existing content — the existing content is the garbage.
- Never set `isError` on the success path (rules.ts skips rule injection when `isError` is true).
- Order-independent by design: no dependence on rules.ts running before/after; the response text carries its own one-line "PDFs are binary — converted automatically" note.
- Guard the whole handler body in try/catch: on unexpected errors return `undefined` (let the original content through) rather than throwing (the runner catches handler errors, but pass-through is cleaner).
- Handles relative AND absolute paths; uses `ctx.cwd` for resolution.
