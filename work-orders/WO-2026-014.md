### Task Summary

**One-sentence description**: Remove seconds-scale latency from the subagent spawn/completion path in the subagent-async extension (deliver results before worktree cleanup, parallelize git calls, cache agent discovery, skip footer quota polling in subagents, add timing instrumentation).

**Goal**: A subagent's result reaches the parent as early as possible and spawn overhead is minimized, with zero change to delivered-result content, branch-preservation semantics, or tool behavior.

### Background (investigation findings, with line refs to verify — they may drift)

1. **Completion path** (`extensions/subagent-async/index.ts` ~1094–1150): the `proc.on("close")` handler awaits `cleanupWorktree()` (~459–485: 4–8 sequential `git` calls: add -A, diff, commit, rev-parse, worktree remove, branch -D) BEFORE `deliverResult()`. This is 1–3s+ of dead time between subagent finishing and parent seeing the result. A comment at ~1136 already notes cleanup "can take seconds".
2. **Spawn path** (`index.ts` ~419–440): `createWorktree` runs 5–7 sequential awaited `git` spawns. Independent ones (two `rev-parse` calls; best-effort stale `worktree remove --force` + `branch -D`) can be parallelized.
3. **Agent discovery** (`index.ts` ~1810, `extensions/subagent-async/agents.ts` ~32–47): `discoverAgents` does `readdirSync` + `readFileSync` on all ~12 agent `.md` files (~150KB) on EVERY `subagent` tool call. No cache.
4. **Footer quota polling** (`extensions/footer-session-id.ts`): a 60s `quotaInterval` fires an HTTP fetch (5s timeout) in EVERY session including subagents, which never see the footer usefully. Subagent sessions are marked with env `PI_IS_SUBAGENT=1` (verify exact var name/value at the spawn site in `index.ts` and the consumption site `extensions/modes.ts` ~248).
5. **No timing instrumentation**: `PI_ASYNC_DEBUG=1` enables an event log (`index.ts` ~159) but no wall-clock durations anywhere.

### Implementation Specification

**Detailed requirements**:

1. **Deliver-before-cleanup** (biggest win). Split the close-handler work into:
   - **Pre-delivery**: only the steps required to produce the result payload's branch/commit info — i.e. `git add -A`, the diff/change detection, `git commit` when changes exist, `git rev-parse HEAD`. Parallelize the independent read-only checks (e.g. diff name-only / diff quiet) where safe.
   - **Deliver**: call `deliverResult()` immediately after the pre-delivery steps, with the exact same payload shape/content as today (branch name + commit hash when changes exist).
   - **Post-delivery** (async, must not block or throw): `git worktree remove` and (in the no-changes case) `git branch -D`. On failure: log via the debug log AND send a steer message to the parent like `[subagent X] warning: worktree cleanup failed: <err> — worktree at <path> may need manual removal`. Never crash the handler; never let a post-delivery failure corrupt the already-delivered result.
   - **`subagent_stop` semantics preserved**: the promise its tool call awaits must resolve once the result is delivered (not after post-delivery cleanup). Check the `resolveOnStop` flow and keep its externally observable timing contract: stop waits for delivery, not for git.
   - **No double delivery**: guard so the result is delivered exactly once across all close/error paths.
2. **Spawn parallelization** (`createWorktree`): run the two `rev-parse` calls concurrently; run the best-effort stale cleanup (`worktree remove --force`, `branch -D`) via `Promise.allSettled` (failures stay non-fatal as today); `git worktree add` remains last, awaited, fatal-on-failure.
3. **discoverAgents cache**: module-level cache keyed by agents-dir path. Validate by `stat`ing the dir and each `.md` file (compare max mtime + file count against cached); re-read only on change. Must not serve stale agents after an agent file is edited (mtime check covers this; note dir mtime alone is insufficient — file content edits don't update dir mtime).
4. **Footer skip**: in `footer-session-id.ts`, do not register the quota polling interval (or the HTTP fetch) when the session is a subagent. Use the same env-var mechanism `modes.ts` uses (verify name/value at the spawn site). Normal (non-subagent) sessions unchanged.
5. **Timing instrumentation**: behind the existing `PI_ASYNC_DEBUG` flag only, log wall-clock durations (via `Date.now()`) for: worktree create (total + per git step), pre-delivery commit steps, deliverResult, post-delivery cleanup, and spawn-to-first-RPC-response. Zero overhead/behavior change when the flag is unset.

**Required test boundary**: the repo's existing extension test runner (discover from `extensions/package.json` scripts; `worktree-guard.test.mjs` shows the style — likely `node --test` or `bun test`). Unit-test the discoverAgents cache (hit/miss/mtime-invalidation) as the primary new automated coverage. The close-handler reorder is lifecycle code that is impractical to unit-test without a live pi; cover it by careful code inspection + the reviewers' structural pass. The orchestrator will run a live end-to-end smoke post-merge — say so in your report rather than claiming a live smoke you didn't run.

**Behavior and failure matrix**:

| # | Case | Expected |
|---|---|---|
| 1 | Subagent completes with uncommitted changes | Result delivered with correct branch + commit hash; worktree removed afterward; branch preserved |
| 2 | Subagent completes with no changes | Result delivered; worktree removed; branch deleted (current semantics preserved) |
| 3 | Post-delivery `worktree remove` fails | Result already delivered intact; warning steer sent to parent; no crash; branch preserved |
| 4 | `subagent_stop` on running subagent | Stop's await resolves at delivery time, not blocked by post-delivery git |
| 5 | Spawn with stale worktree dir + stale branch | Best-effort cleanups run in parallel and non-fatally; `worktree add` succeeds |
| 6 | Two `subagent` spawns, agents dir unchanged | Second spawn performs no `readFileSync` of agent files (cache hit) |
| 7 | Agent file edited between spawns | Cache invalidated by mtime; fresh content served |
| 8 | Session with `PI_IS_SUBAGENT` set | No quota HTTP interval registered |
| 9 | Normal session (no env var) | Quota polling behaves exactly as before |
| 10 | `PI_ASYNC_DEBUG` unset | No timing log lines; no measurable overhead |
| 11 | `PI_ASYNC_DEBUG=1` | Duration lines present for worktree create, commit steps, delivery, cleanup |

**Integration contract**: the extension registers tools/events with pi's extension API — do not change any tool name, parameter schema, or the delivered-result message shape (parents and the orchestrator gate parse it). The reviewer tracker (`/tmp/pi-subagent-*.reviewers.json`) and meta files are untouched.

**Reference patterns**: follow the existing `git()` helper and async style in `index.ts`; follow `modes.ts` for env-var gating; follow `worktree-guard.test.mjs` for test style.

### Invariants

**Cross-file conventions**:
- The delivered result message format is parsed by parent sessions — its structure (prefix lines, session stats, isolation note, final output) must be byte-compatible in shape.
- `PI_IS_SUBAGENT` semantics must match how `modes.ts` checks it (same var, same truthiness convention).

**Default values to preserve**:
- Branch naming `pi-subagent-<id>`, worktree location under the OS temp dir, meta/tracker file locations — all unchanged.

**Ordering assumptions**:
- Result delivery must happen exactly once, strictly after the commit-producing git steps, strictly before/without waiting for worktree removal.
- `git worktree add` must remain after stale-cleanup attempts.

**Error handling conventions**:
- Best-effort cleanup failures (stale removal at spawn, post-delivery removal) are logged + surfaced as warnings, never fatal.
- Pre-delivery git failures keep today's behavior (result delivered with failure info, worktree/branch left for inspection — verify and preserve whatever the current failure path does).
