## Implementation Specification

### The matrix (7 runs)

For each case in `benchmarks/design-fork/cases.txt` (01-binding-name … 07-no-fold-abstention), run exactly as the smoke run did (which is proven):

```bash
IMPLEMENT=1 benchmarks/run.sh design-fork openrouter deepseek/deepseek-v4-flash high deepseek-v4-flash <case-slug>
```

- Same flags as the smoke run: `--thinking high`, IMPLEMENT mode (clone at base, edit/write enabled, diff saved before cleanup).
- Then grade each saved diff: `benchmarks/design-fork/grade.sh <case-slug> benchmarks/design-fork/results/<case-slug>.deepseek-v4-flash.diff`
- **Reuse the warm grade caches** at `benchmarks/runs/grade-<case>/` (from WO-2026-044 self-validation) — do NOT rebuild from scratch; only the incremental rebuild for the applied agent diff should happen.
- Let every pi invocation run to completion (flash converged in the smoke run in ~16 min; some cases may take longer — that's data, not a bug). Non-convergence (>20 min with no progress) is a wart — log it and move on, do NOT kill-and-retry mid-matrix.
- Parallelize at most 2 runs at a time if wall time is a concern — but the grade-cache clones are single-threaded-safe per case (one grade at a time per case dir).

### Deliverable 1 — the score table

Per case: {works, purity, minimality, caseScore} from grade.json + from the usage/timing json: input/output/reasoning tokens, cost, wall time, pi exit. Aggregate: sum(caseScore)/35, plus the purity-by-case breakdown (how many cases took the pure branch). Include the diff line counts vs gold per case (minimality context).

### Deliverable 2 — the wart report (THE point of this WO)

Flag EVERY issue the run surfaces, per case, with evidence (quote the file/line or log). Wart classes:
1. **Vacuous test signal** — the held-out test passes without exercising the fix (the reviewer's case-05 catch from 044; check others the same way: does the test fail at base and pass with the fix?).
2. **Telegraphing** — the prompt leaked which branch is right (compare the agent's diff against the prompt text; if the prompt nudged the pure construct by name, that's a telegraph).
3. **Grader misbehavior** — purity scored wrong (agent clearly took the trap but scored 2, or vice versa), apply failures misreported, stale-cache interference, wrong base checkout.
4. **Base-tree issues** — base doesn't build, held-out test flaky at base, the tmp-dir/verify_llm_doc preflight quirks, profile detection wrong.
5. **Non-convergence / weird agent behavior** — empty diff, giant diff (gold-plating), the agent editing test files (should be filtered — verify), aborting mid-task.
6. **Cross-case consistency** — the same wart appearing in multiple cases (e.g. a purity-spec pattern that's systematically wrong).

For each wart: `case / class / severity (low-mid-high) / evidence / suggested fix direction`. Also state which cases scored clean (no warts) — those are the trustworthy anchors for the future matrix.

### Deliverable 3 — recommendations

One short section: what to fix in WO-2026-046 (the fix WO), what to defer, and whether any case should be dropped/replaced. Your opinion matters here — you ran the thing.
