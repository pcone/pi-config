## Implementation Specification

### Detailed requirements

**1. New `silenceTimeoutMs?: number` param** on `SubagentParams` (~2097), description: "Kill the subagent if it makes no progress (no tool calls and no assistant messages) for this many milliseconds. Default 300000 (30 min). 0 or negative disables the auto-kill. Stage-1 wake-up warnings are unaffected."

**2. Last-activity tracking** — per child record (RS): `lastActivityMs`. Updated on: any log line written to the child's log (existing logEntry path), and tool-execution events (the extension already receives `tool_execution_start`/`tool_execution_end` events at 1195-1204/1394-1408). Assistant messages arrive via the RPC "prompt"/message path — a message from the child also counts as activity (update on RPC messages received). Keep it simple: one timestamp, updated on the union of those signals.

**3. Stage-2 auto-kill** — a `setTimeout` chain per child (mirror the stage-1 watchdog's existing pattern at 1737-1759): when `now - lastActivityMs > silenceTimeoutMs` AND the child is not already stopped/killed/completed → invoke the existing kill path (SIGTERM → SIGKILL after grace; reuse the `subagent_kill` internals, ~2839-2910 — idempotent, cancels stale watchdog timers). Deliver the result to the parent as a user message with marker `[Killed via progress-timeout]` (mirroring the `[Killed via subagent_kill ...]` marker) so the parent's `wait` resolves. The session file must remain intact for `subagent_resume`.

**4. Stage-1 interaction** — the existing 5-min stale-turn wake (parent alert, no kill) stays exactly as-is. When stage-2 fires, cancel this child's stage-1 wake timer (idempotent cleanup). If the parent already stopped/killed the child, stage-2 must be a no-op (guard on state, same pattern as kill's idempotency).

**5. Mirror test rows** — rows for: (a) silence tracking updates on log/tool/message signals; (b) stage-2 fires at `silenceTimeoutMs` when silent; (c) `silenceTimeoutMs: 0` disables; (d) active child past the threshold not killed; (e) stage-2 no-op after explicit kill/stop. The unit boundary cannot verify real process kill + delivery — post-merge E2E is the real gate.

### Behavior and failure matrix

| Case | Expected |
|---|---|
| Child silent for `silenceTimeoutMs` (default 30 min) | Auto-kill; `[Killed via progress-timeout]` delivered; wait resolves |
| Child active (any signal within window) | Never killed, even past threshold wall-clock |
| `silenceTimeoutMs: 0` (or negative) | Stage-2 disabled entirely |
| Child already stopped/killed/completed | Stage-2 no-op |
| Stage-1 5-min wake | Unchanged (parent alert only) |
| Killed session | Session file preserved; `subagent_resume` works |
| Slow-but-healthy long task | Survives if it emits any signal inside the window; otherwise extendable via param |
