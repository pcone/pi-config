### Task Summary

**One-sentence description**: Add a one-shot soft "wrap up now, return a partial result" nudge to subagents at 450 turns (keeping the 500-turn hard kill), and lower the auto-checkpoint nudge threshold for deepseek models from 300000 to 250000 tokens.

**Goal**: Subagents that approach the 500-turn hard cap return a partial completion report instead of being killed mid-turn; subagents get nudged toward checkpointing at 250K tokens of session context instead of 300K.

### Implementation Specification

**Detailed requirements**:

1. **`.pi/auto-checkpoint.json`**: change `"threshold": 300000` → `"threshold": 250000` for exactly these three model entries: `deepseek/deepseek-v4-flash`, `deepseek/deepseek-v4-flash-0731`, `deepseek/deepseek-v4-pro`. Do not touch any other entries (glm-5.2, arcee, qwen, minimax, anthropic, openai, gemini stay as-is) and do not change `cooldownTurns`/`cooldownMs` values.

2. **`extensions/subagent-async/index.ts`** — soft turn nudge:

   a. Add constant next to `MAX_TURNS_HARD = 500` (line 24):
      ```ts
      const TURN_NUDGE_SOFT = 450; // warn once before the hard 500-turn kill
      ```

   b. Add `turnNudged: boolean;` to the `RunningSubagent` interface — place it directly after `stoppedExplicitly: boolean;`.

   c. Initialize `turnNudged: false,` at BOTH `RunningSubagent` construction sites:
      - the main `spawnSubagent` rs object (line ~819, after `stoppedExplicitly: false,`)
      - the recovered-session rs object (line ~1642, in the same spot)

   d. In the `message_end` handler, after the usage-stats accumulation block and BEFORE the `// Hard turn limit` check, insert:
      ```ts
      // Soft turn nudge: warn once near the hard cap so the agent can wrap
      // up with a partial result instead of being hard-killed mid-task.
      if (!rs.turnNudged && rs.progress.turns >= TURN_NUDGE_SOFT) {
          rs.turnNudged = true;
          const nudge =
              `[Turn-limit warning] You have used ${TURN_NUDGE_SOFT} of the ${MAX_TURNS_HARD}-turn ` +
              `hard limit for this subagent run; the process will be killed at ${MAX_TURNS_HARD} turns. ` +
              `Do NOT start new work and do NOT launch reviewers. Wrap up now: complete or abandon the ` +
              `current step, then emit your completion report with **status: partial** (or blocked) — ` +
              `summarize what was completed, what remains, and any open issues. Your next text-only ` +
              `message is your final output.`;
          try {
              rpcSend(rs.stdin, { type: "prompt", message: nudge, streamingBehavior: "steer" });
              logEntry(`\x1b[33m[turn-limit] soft nudge injected at ${rs.progress.turns} turns\x1b[0m`);
              debugLog(`turn-nudge: soft nudge at turns=${rs.progress.turns} child=${rs.sessionId}`);
          } catch (e) {
              debugLog(`turn-nudge: rpcSend failed: ${e instanceof Error ? e.message : String(e)}`);
          }
      }
      ```
      The nudge must NOT return early — the handler continues to the hard-limit check and completion detection as before.

   e. Suppress the review-gate for nudged agents: in the completion-detection branch, change the guard condition from
      `if (required && required.length > 0 && !rs.stoppedExplicitly) {`
      to
      `if (required && required.length > 0 && !rs.stoppedExplicitly && !rs.turnNudged) {`
      Rationale: an agent told to wrap up under turn pressure must be allowed to emit its partial report as a text-only message without the gate forcing reviewer launches (which would burn the remaining turns and end in the hard kill). The orchestrator's mechanical gate is report-driven — it keys off `complete` reports, and a nudged agent is instructed to report `partial`.

**Required test boundary**: `bun test` (all tests in `tests/` — they import `extensions/subagent-async/index.ts`, so they catch syntax/import/parse errors in the modified file). There is no unit-testable boundary for the inline nudge dispatch (it lives in a closure); behavioral verification is by orchestrator diff review + the existing manual e2e scripts.

**Behavior and failure matrix**:
- Turns < 450: no nudge, no flag set, hard kill still at 500.
- Turns == 450 (first time crossing): nudge dispatched exactly once via steer; flag set; handler continues.
- Turns 451–499: no re-nudge (flag already set).
- Turns >= 500: hard kill fires exactly as today (`proc.kill("SIGTERM")` + `HARD_KILL_DELAY_MS` SIGKILL fallback). Unchanged.
- Agent emits text-only final message AFTER the nudge: review-gate soft-prompt is skipped (turnNudged true); session closes normally as today (isDone, stdin.end()).
- Agent emits text-only final message BEFORE the nudge (< 450 turns): review-gate behaves exactly as today.
- `rs.stdin` null/destroyed at nudge time: rpcSend failure is caught and logged; no crash.
- Recovered sessions (line ~1642): turnNudged initializes false; if a recovered session's parsed turn count is >= 450 the nudge may fire — same as a fresh session.
- Auto-checkpoint: deepseek models threshold resolves to 250000 (absolute, >= 1 → tokens, per the extension's threshold semantics); all other models unchanged.
