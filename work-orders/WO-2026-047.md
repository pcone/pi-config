## Implementation Specification

### 1. `tests/todo-injection.test.ts`

A fake `ExtensionAPI` + `ctx`, then drive handlers/tool and assert. Sketch:
```ts
import { describe, it, expect } from "bun:test";
import todoExtension from "../extensions/todo";

function createPiStub() {
  const handlers = new Map<string, (...args: any[]) => any>();
  const tools = new Map<string, any>();
  const pi: any = {
    events: { emit: () => {} },
    on: (event: string, handler: any) => { handlers.set(event, handler); },
    registerTool: (def: any) => { tools.set(def.name, def); },
    registerCommand: () => {},
  };
  return { pi, handlers, tools };
}

// ctx with a test-controlled branch; mode !== "tui" makes refreshWidget a no-op.
function ctxStub(branch: any[] = []) {
  return {
    mode: "rpc",
    sessionManager: { getBranch: () => branch },
    ui: { setWidget: () => {} },
  };
}

// A branch carrying one todo toolResult snapshot (what reconstructState consumes).
function branchWith(todos: any[], nextId: number, doc?: string) {
  return [{
    type: "message",
    message: { role: "toolResult", toolName: "todo", details: { action: "list", todos, nextId, doc } },
  }];
}
```
Load once per test (module state is closure-scoped per `todoExtension(pi)` call, so each test must
re-load to start clean): `const { pi, handlers, tools } = createPiStub(); todoExtension(pi);`

Drive the tool via `tools.get("todo").execute("tc1", params, undefined, undefined, ctxStub())`.

### 2. Behavior matrix (each row = one `it`)

1. **Re-prime after compaction (headline)**: `session_start({}, ctxStub([]))` (fresh, empty) →
   `execute` add "Task one" + add "Task two" → `session_compact()` → first `before_agent_start()`
   returns `{ message: { customType: "todo-injection", display: false, details: { count: 2 }, content } }`
   where `content` contains both `#1: Task one` and `#2: Task two` → second `before_agent_start()`
   returns `undefined` (flag cleared — one-shot).
2. **Resume injects**: `session_start({}, ctxStub(branchWith([{id:1,text:"X",status:"in_progress"}], 2)))` →
   `before_agent_start()` returns a message whose `content` contains `[>] #1: X`. (pendingTodoInjection
   set by session_start because todos.length > 0.)
3. **No injection on a fresh empty session**: `session_start({}, ctxStub([]))` → `before_agent_start()`
   returns `undefined`.
4. **Adding tasks without a re-prime event does not inject**: `session_start({}, ctxStub([]))` →
   `execute` add → `before_agent_start()` returns `undefined` (pending flag still false; injection is
   event-driven, not every-turn).
5. **All-done list → no injection (empty-block guard)**: `session_start({}, ctxStub(branchWith([{id:1,...done},{id:2,...done}], 3)))` →
   `before_agent_start()` returns `undefined` (todos.length is 2 so the flag WAS set, but
   `renderTodoBlock` returns `""` for all-done → handler's `if (!block) return` suppresses the message).
6. **session_tree parity**: `session_tree({}, ctxStub(branchWith([{id:1,text:"Y",status:"pending"}], 2)))` →
   `before_agent_start()` returns a message whose `content` contains `[ ] #1: Y`.

Assert message structure (`customType`, `display: false`, `details.count`) where a message is expected;
assert `undefined` where injection must not happen. For `content`, assert it contains the expected
`#id: text` / mark substrings rather than re-deriving the whole block (the full-block output is
already pinned by `tests/todo-render.test.ts`).

## Invariants

- **Fake must be faithful to the real event contract**: `on(event, handler)` captures by event name;
  handlers are invoked with the same positional args the real pi would pass (`(_event, ctx)` for
  session_start/session_tree/tool_result; `()` for session_compact/before_agent_start). Do not invent
  args the real runtime doesn't pass.
- **Each test re-loads the extension** (`todoExtension(pi)` on a fresh stub) so module state
  (`todos`, `pendingTodoInjection`) doesn't leak between tests.
- **ctx stub is non-tui** (`mode: "rpc"`) so `refreshWidget` no-ops; `sessionManager.getBranch()` is
  test-controlled; `ui.setWidget` is a no-op. The fake must not depend on real pi-tui types.
- **No real pi runtime / no network / no fs** beyond importing the extension module.
- **The one-line `invalidate` addition is the only `extensions/todo.ts` change** — do not touch the
  injection logic, the widget, `renderCall`/`renderResult`, or any tool action.
- **No `tsconfig`/`tsc` introduced**: there is none in the repo and pi typechecks nothing at load;
  the `invalidate` fix is verified by convention (matches footer-session-id) + the suite still
  passing. Do not add a tsconfig or a tsc dependency.
