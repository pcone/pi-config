**Execution order — parallel runs, sequential grading:**
1. **All 42 pi invocations in parallel** (or tight batches of 6–8 if the machine thrashes — one invocation per model at a time keeps per-model results streaming). The runner's per-invocation isolation (fresh clone, nanosecond-timestamped scratch, case+slug-qualified results) makes concurrent pi runs safe. Launch each via background + nohup-style so tool-call timeouts don't kill them; **never a single bash command that runs >15 min** (the silence-based progress-kill ate the pilot's long poll — poll in short chunks, `sleep 240` max, with progress reporting between).
2. **Grading: STRICTLY SEQUENTIAL, one case at a time.** The grade caches (`benchmarks/runs/grade-<case>/`) are keyed by CASE, not model — concurrent grades of the same case would corrupt the cache. Grade all 6 models' diffs for case 01, then case 02, … case 07. Reuse the warm caches; each agent diff applies incrementally.
3. No kills/retries mid-matrix — a failed run is a data point (note it, continue). Non-convergence (>25 min on one run with no progress) is a wart, logged not retried.
