## Implementation Specification

### Detailed requirements

**1. New `workOrderPath?: string` param** on `SubagentParams` (Type.Object at ~2097), description: "Repo-relative path to the work order this task executes (e.g. `work-orders/WO-2026-037.md`). When set, the harness reads the work order from the parent checkout at spawn time and derives the review-gate decision from its declared `review_policy` — the WO is the single source of truth. The spawn hard-fails with a loud error if the file is missing or unreadable."

**2. Spawn-time WO read + parse** (in the subagent tool execute, before/at spawnSubagent):
- Resolve against `cwd` (the parent repo root; `params.cwd ?? ctx.cwd`).
- Missing/unreadable → return a tool error object (like the unknown-agent error at ~2183): `content: [{type:"text", text: "...workOrderPath file not found: <path>. Spawn aborted — pass a valid repo-relative path or omit workOrderPath."}]` — do NOT spawn, do NOT create a worktree.
- Parse: find `**review_policy**:` in the file and read the **first word** after the colon. `skip` → skip; anything else (including `required`, absent, or the template's literal `required | skip`) → required. First-word semantics matters: the template line `- **review_policy**: required | skip` must parse as required (the existing task-text regex `/^\s*-\s*\*\*review_policy\*\*:\s*skip\b/m` already has this property — "required | skip" fails it because `skip` is not the first token; mirror that semantics for the file parse).

**3. Gate decision (single source)** — currently `reviewParentRequirements` is computed inline in spawnSubagent's RS record (~1038) as `(reviewPolicy === "skip" || taskRegex) ? undefined : agent.reviewParentRequirements`. Change to:
- `workOrderPath` present → effective policy = parsed WO value (WO **wins** over the tool param on disagreement).
- `workOrderPath` absent → current behavior (param OR task-text canonical bullet).
- `effectivePolicy === "skip"` → `reviewParentRequirements: undefined`; else `agent.reviewParentRequirements`.

**4. Skip injection** — `maybeInjectReviewPolicySkip` (~2156) currently injects the canonical bullet when the param is skip. Change its inputs to the *effective* policy: when effective is skip → inject (existing behavior); when the WO declares required but the param says skip → do NOT inject (WO wins). The function's docstring must be updated (its "Single source of truth: the tool arg" claim becomes "the work order, when `workOrderPath` is set; else the tool arg").

**5. Orchestrator routing rule** — append to `agents/orchestrator.md` (verbatim content from decision 014, "Routing rule" section): skip criteria (complexity-centric, no file counts), require-criteria incl. the hard harness clause, and: "always pass `workOrderPath` on implement dispatches — the gate reads the WO, not the task text."

**6. Mirror test row** — extend the existing mirror/standalone test pattern (see `extensions/subagent-async/test-carry-uncommitted.cjs` and the mirror suite referenced by WO-2026-035): rows for (a) WO-declares-skip suppresses the gate decision without param; (b) WO-declares-required keeps gate live despite param skip; (c) missing WO path → loud error, no spawn; (d) param-only (no WO) → current behavior preserved. The unit/mirror boundary cannot verify spawn behavior end-to-end — the post-merge E2E battery is the real gate (below).

### Behavior and failure matrix

| Case | Expected |
|---|---|
| WO declares `- **review_policy**: skip ...` + `workOrderPath` passed, no param | Gate suppressed; skip bullet injected into task |
| WO declares `required` + `workOrderPath` passed + param `skip` | Gate LIVE (WO wins); NO skip injection |

| Tool description / README signature | Documents `workOrderPath` |
