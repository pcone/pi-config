### Task Summary

**One-sentence description**: Make `compaction-model.ts` yield the checkpoint path before any fleet call, and stop swallowing fleet failures on the paths it does own.

**Goal**: The stored summary of a checkpoint compaction is always the text `checkpoint.ts` composed. `/compact` and auto-compaction still get the fleet rewrite. No fleet failure silently decides who owns a summary.

### Ruling input (owner 2026-10-31 → `decisions/checkpoint/003`)

| case | behaviour after this order |
|---|---|
| manual + `[CHECKPOINT]` marker (the `checkpoint` tool) | `compaction-model.ts` returns `undefined` **before** resolving a model or calling `compact()`; checkpoint's composed summary stands |
| manual, no marker (`/compact`) | fleet rewrite, unchanged |
| auto (`threshold` / `overflow`) | fleet rewrite, unchanged |
| fleet call fails (any reason, on the paths above) | surface it through `ctx.ui.notify` at `error` level: no override, no silent `undefined` |
| model unresolvable / auth missing (non-checkpoint paths) | surface at `warning` (today's behaviour), keep returning `undefined` |

Common rows: the compaction boundary (`firstKeptEntryId`, `tokensBefore`) is copied from `preparation` in every path; `[CHECKPOINT]` stays in the stored text; checkpoint's side effects (archive, injection, continuation) are unaffected — its handler runs first and this order does not touch it.

### Premise — VERIFIED 2026-10-31 against the installed pi 1.4.0

- Runner resolution: `dist/core/extensions/runner.js:812-836` — last non-null result overwrites, `cancel` short-circuits, a throw calls `emitError` and leaves the prior non-null standing. Results replace, never merge.
- `checkpoint.ts` emits `customInstructions: "[CHECKPOINT]\n<composed summary>"` (`:444`) and returns `{compaction:{summary, firstKeptEntryId, tokensBefore}}` (`:522-526`); `MARKER` is `"[CHECKPOINT]"` (`:32`) and the same file already dispatches on `customInstructions?.includes(MARKER)` (`:499`).
- `compaction-model.ts:56-59` returns `{compaction: result}` from a full `compact()`; `settings.json` loads it after `checkpoint.ts`.
- **Live evidence that the override is armed on 1.4.0**: session `01a190c3`, three checkpoints on 2026-10-31 — #1 (`a7020928`) is verbatim `checkpoint.ts` text with no `details`/`usage` (fleet call failed, swallowed), #2 (`0dab9346`) and #3 (`a46590f4`) are fleet rewrites with `details` + `usage`. The 0.83.0 diagnosis "the override never fires" (`checkpoint-sanity-check-2026-10.md` §5.2) no longer holds.

**Falsify probe**: drive both real handlers through runner semantics with a checkpoint-marked event (row R1). If the marker path cannot be distinguished, the mechanism is not available:

> **PREMISE FALSIFIED** — stop, report with the captured event, land nothing.

### Preparatory refactor

**none** — the change is the body of one handler (`compaction-model.ts`'s `session_before_compact`), replacing an unconditional call with a predicate and a non-silent failure path. Census: `rg -n "session_before_compact" extensions/` returns exactly two — `checkpoint.ts` (producer) and `compaction-model.ts` (overrider). No second summary-selection path exists to fold, and none may be added.

### Rejected alternatives

- **Fleet rewrite for checkpoints** — rejected 2026-10-31 (`decisions/checkpoint/003`): non-deterministic (measured: #1 verbatim, #2/#3 rewritten in one session) and it demotes authored text to a summariser hint.
- **Authored text as `customInstructions`, fleet text as the summary** (the shape #2/#3 took) — rejected 2026-10-31, same record: the marker was a hint, not an owner.
- **Holding ownership by leaving the fleet call to fail** — rejected 2026-10-31, same record: a provider failure is not a policy.

### Implementation Specification

1. **Predicate.** In `compaction-model.ts`'s `session_before_compact`, read `event.customInstructions` and return `undefined` immediately when it contains the checkpoint marker — before `modelRegistry.find`, before auth, before `compact()`. Share the marker constant: import or re-export it from a single module rather than writing the literal `"[CHECKPOINT]"` a second time. If the marker cannot be imported without changing `checkpoint.ts` (out of scope), export it from a small shared module and report the deviation; do not duplicate the literal.
2. **Failure surfacing.** The existing `compact()` catch returns `undefined` silently. Keep returning `undefined` (the specified no-override outcome) but notify at `error` level with the model spec and the message. The `signal?.aborted` arm stays silent (user cancel).
3. **Boundary.** Unchanged: `compact()`'s result carries `firstKeptEntryId`/`tokensBefore`; do not recompute or override them.
4. **Doc comment.** Update the module header: it currently claims it forces the fleet model for `/compact` *and* auto-compaction; it now also yields checkpoint compactions to `checkpoint.ts` (owner 2026-10-31, `decisions/checkpoint/003`).

**Required test boundary**: the two real extension modules' `session_before_compact` handlers driven through pi's runner semantics (last-non-null, `cancel` short-circuit, throw-leaves-prior-standing), with the fleet `compact()` mocked at its module seam. A test that calls an extracted predicate directly is INADEQUATE — the ruling's enforcement point is the handler chain.

**Behavior and failure matrix**:

| row | case | asserts |
|---|---|---|
| R1 | checkpoint-marked event, fleet call mocked and instrumented | `compact()` **never called** (spy count 0); stored summary is checkpoint's text verbatim; boundary equals `preparation`'s |
| R2 | `/compact` event, no marker | `compact()` called once; its summary stored; boundary equals `preparation`'s |
| R3 | auto event (`threshold`), no marker | as R2 (pin both `threshold` and, if cheap, `overflow`) |
| R4 | non-checkpoint event, `compact()` rejects | no override (prior result, or none, stands); `notify` called at `error` with the message |
| R5 | non-checkpoint event, model unresolvable | `notify` at `warning`; `compact()` never called; no override |
| R6 | non-checkpoint event, user abort (`signal.aborted`) | no notify, no override |
| R7 | checkpoint event, side effects | archive/injection/continuation unaffected by this handler returning early (assert the checkpoint handler's own calls still ran) |
| R8 | marker survival | `[CHECKPOINT]` present in the stored summary text |

Mutation control: delete the predicate (make it unconditional again) and show R1 red, R2/R3 green; restore. A row that stays green under the mutation is a no-op control and must be reported as such.

**Integration contract**: `compaction-model.ts` is one of two `session_before_compact` handlers. It consumes `SessionBeforeCompactEvent` (`customInstructions`, `preparation`, `signal`) and returns `undefined | {compaction}`. `checkpoint.ts` runs first and its result is the fallback this handler must stop overwriting.

**Reference patterns**: `extensions/checkpoint.ts:499` for the marker dispatch shape; `tests/e2e-checkpoint.test.ts` for the harness conventions (real runner semantics, mocked seams).
