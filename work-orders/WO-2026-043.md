## Implementation Specification

### Detailed requirements

1. **Root cause**: `dispatchKillSignals` (line ~L1935) computes `const alreadyDead = rs.proc.killed || rs.proc.exitCode !== null;`. On a recovered/pre-reload session the `RunningSubagent` entry is reconstructed from disk and `proc` is null (the child process no longer exists / was never re-attached). `rs.proc.killed` then throws, propagating out of the tool `execute` body as the observed TypeError. The stop path at ~L3048 (`rs.proc.kill("SIGTERM")`) has the same latent null risk.
2. **Fix, in `dispatchKillSignals`**: before touching `rs.proc`, add a null-proc branch:
   - Keep the existing flag ordering (`rs.killedExplicitly = true; rs.killedVia = via;` first — the close handler and `killedMarker` depend on the flags, and this must remain true for the recovered-session path).
   - `if (!rs.proc)` → append the kill marker line via `appendRunningLogLine` with a distinct label ("process handle unavailable (recovered/pre-reload session) — marked killed, no signal sent"), return `{ alreadyDead: true }` (nothing to signal). Do NOT dereference `rs.proc` anywhere on this path — including the SIGKILL setTimeout callback (~L1944) which must also be skipped.
   - The tool body (~L3094) should report the null-proc case distinctly: when `dispatchKillSignals` returns `alreadyDead` because there was no process, the message should say the session was marked killed but no live process existed to signal (recovered session) — not the generic "already dead" wording.
3. **Stop path (~L3048)**: guard the `rs.proc.kill("SIGTERM")` + its SIGKILL callback the same way (skip signals when `!rs.proc`; the close-handler/waiter path still resolves).
4. **Do not change** the idempotency contract, the close-handler-owns-delivery contract, or the marker wording for the existing paths.

### Behavior and failure matrix

| Case | Expected |
|---|---|
| `dispatchKillSignals` with live proc (regression) | SIGTERM→SIGKILL as today, `alreadyDead: false` when alive |
| `dispatchKillSignals` with null proc | No throw; flags set; marker logged with "process handle unavailable"; `{ alreadyDead: true }`; no signal attempted |
| Tool `subagent_kill` on recovered session | Returns a distinct message (marked killed, no process existed); no TypeError |
| Stop path on null proc | No throw; waiter still resolves |
| Idempotency (second kill call) | Unchanged — no-op with the existing message |
