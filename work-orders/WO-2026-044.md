## Task Summary

**One-sentence description**: Build the design-fork benchmark in `~/Developer/model-benchmarking` — an implementation-task runner mode (diff-as-artifact grading, per the agreed design), a 7-case corpus mined from tfd's git history (each case = anchored task prompt, base commit, gold patch, held-out test, deterministic purity spec), a grader, self-validation, and one end-to-end smoke run.

**Goal**: The benchmark grades which branch of a designed fork a model takes when implementing: the pure branch (language-native / idiomatic / minimal) or the trap (hand-rolled reimplementation, hidden global state, less-pure shape). Scoring per the agreed design: per-case `{works, purity 0/1/2, minimality 0/1/2}` → case score = `works ? (1 + purity + minimality) : 0` (0–5); aggregate = fraction of max + purity-by-case breakdown. One fork per task. Grading surface = **Option A: diff applied to a pristine clone** (test-path edits filtered; held-out F2P test applied at grade time; never trust the agent's live checkout).

## Design (read fully before implementing)

Design record: none yet — this WO authors `decisions/002-design-fork-benchmark.md` in model-benchmarking (your deliverable 7). The agreed design (orchestrator + user decisions):

1. **Fork concept**: each case is an implementation task mined from tfd history where a real fork existed (or exists live): (a) **reimplementation forks** — hand-rolled X where the language/established mechanism exists; (b) **purity forks** — hidden global/thread-local state, `unsafe`, panic-paths, escape-hatch flags where pure/parameterized/established machinery exists. The prompt opens the fork WITHOUT telegraphing which branch is right.
2. **Grading surface (Option A)**: agent works in a fresh clone at `base_commit` with `edit`/`write` ENABLED (bash-heredoc writes land in `git diff` regardless — the diff is the gradable surface, tool-agnostic). Grade time: `git diff base_commit` → filter out test paths → apply to a FRESH clone of `base_commit` → apply the held-out F2P test (never shown to the agent) → compile + run. Purity greps run on the filtered diff.
3. **Three signals per case**: works (0/1, deterministic test signal), purity (0/1/2, deterministic grep spec — 0=trap taken, 1=hybrid/mixed, 2=pure branch), minimality (0/1/2 — diff vs gold, hand-checked at review, noted as soft signal in Phase 1).
4. **Contamination posture**: tfd is PRIVATE (github.com/pcone/tfd returns 404 unauthenticated) — tasks and answers are private by construction. Keep the corpus private (no public copies). Fresh clone per run, `--no-session` (existing). Author ≠ grader: the review gate (different model) validates case prompts; do not self-grade.
5. **Abstention variant** (case 07): the pure branch can be "don't add the feature" — graded as empty-src-diff + justification referencing the existing mechanism.

### Prompt authoring rules (the review gate checks these)

- **Anchored, not bare**: embed the surrounding compiler state (the relevant types, the existing mechanism, the requirement) so every model starts from the same info regardless of training-data coverage — the for-loop benchmark's proven pattern.
- **Open the fork, never telegraph**: the prompt describes the REQUIREMENT and the surrounding machinery, not "which branch to take". It must not contain the purity.spec's keywords as advice (e.g. case 02's prompt never says "avoid global state"). A model that reads the actual code will encounter the live trap pattern (cases 02/03/04) — that IS the fork.
- **Concrete, scoped**: the task is implementable in a session (small diff vs gold, one file or a small file cluster). Say what "done" means behaviorally (the test signal's requirement, phrased behaviorally — never naming the held-out test).
- **No test names**: never reference the held-out test or its file paths.

### The runner mode (`run.sh`)

Per the Scope. Ensure the `results/<slug>.diff` is written BEFORE the cleanup trap and is byte-identical to what grade.sh will grade. The smoke run must exercise this path end-to-end.

### The grader (`grade.sh`)

Usage: `benchmarks/design-fork/grade.sh <case-slug> <diff-file> [--gold | --trap]` plus a self-validation mode. Requirements:
- Fresh clone of `$TFD_SOURCE` (default `~/Developer/tfd`) at the case's base SHA (full history is available in a local clone; `git clone` then `git checkout <base>`).
- Apply the agent diff with test paths filtered (paths matching the case's test files / `*/tests/*` / `*test*.rs` per case — the filter set lives in `case.md`). `git apply` cleanly or `works=0` with the apply error captured.
- Apply `test.patch` (the held-out tests) AFTER the agent diff.
- `cargo test` (or the case's targeted test invocation) in the workspace — build errors → `works=0`. Cache built clones per case under `SCRATCH_ROOT/grade-<case>/` (reuse across runs; the base tree is identical per case).
- `purity` via `purity.spec` greps on the filtered agent diff (not the whole tree) — spec format: for each fork signal, the trap grep (e.g. `thread_local!`) and the pure check (e.g. `binding_name` present on FunctionDef and no `MONOMORPHIZED_FN_NAMES_BY_ID`); 2=clean pure, 1=mixed (trap signal present but pure construct also present / partial), 0=trap.
- `minimality`: diff line count vs gold line count ratio (≤1.5× = 2, ≤3× = 1, else 0) — soft signal, hand-checked at review.
- Emit `grade.json`: `{case, works, purity, minimality, caseScore, details{applyLog, testLog, purityHits, diffStats}}`.
- **Self-validation (required)**: gold patch → works=1/purity=2 (or the case's defined gold outcome); a fabricated trap diff (use the historical impure branch for 01/05/06, or a minimal trap snippet for the reference-gold cases) → purity=0; a truncated/garbage diff → works=0. All cases must pass self-validation before the smoke run.
